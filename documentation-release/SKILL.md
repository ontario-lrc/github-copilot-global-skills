# Documentation and release preparation

## Procedure
1. Establish audience, purpose, scope, and required artefacts.
2. Gather authoritative evidence from requirements, architecture, source, configuration, and verified test results.
3. Identify existing documentation conventions and source-of-truth locations.
4. Update only relevant documentation.
5. Prepare release notes, changelog entries, migration/upgrade guidance, compatibility notes, and delivery checklists only when applicable.
6. Validate examples, commands, links, diagrams, terminology, and version-specific statements.
7. Mark unknown or unverified information rather than guessing.
8. Report changed files, sources, validation, and outstanding decisions.

Do not modify application source code, invent release facts, publish packages, create releases, or deploy software.
