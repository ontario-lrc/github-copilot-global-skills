# Security assessment

## Procedure

1. Confirm scope, assets, data sensitivity, actors, environment, and exclusions.
2. Identify trust boundaries, attack surfaces, entry points, and plausible threat scenarios.
3. Select relevant domains: identity, access control, input handling, data protection, cryptography, APIs, dependencies, configuration, logging, infrastructure, and availability.
4. Inspect architecture, source, configuration, and dependency evidence without modifying files.
5. Research current primary sources, vendor advisories, and recognised security guidance where material.
6. Validate each finding against a concrete weakness or plausible attack path.
7. Assess impact, likelihood, severity, and confidence separately.
8. Recommend proportionate remediation and independent verification.
9. State exclusions, unassessed areas, and residual uncertainty.

## Authority boundary

This skill is read-only. Do not edit files, execute commands, run tests or scanners, generate exploit code, probe live systems, or perform active penetration testing. Any active validation must be a separately scoped and explicitly authorised activity performed by an appropriately authorised capability, not by this assessment workflow.

Never claim comprehensive security or compliance from a limited review.
